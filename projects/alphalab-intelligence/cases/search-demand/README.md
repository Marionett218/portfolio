## Business problem

Search-volume data can provide an early signal of how interest in diagnostic services differs across regions and changes over time.

The analytical task was to turn raw keyword-level search demand into a decision-support view that makes it possible to answer questions such as:

- Which diagnostic areas generate the highest search demand?
- How does demand differ across regions?
- Which areas are growing or declining?
- Which individual search queries drive demand within a diagnostic area?
- How do current search volumes relate to recent growth?

The purpose of the case is to demonstrate how search-demand data can be transformed into a structured market-intelligence instrument.

## Analytical solution

The solution organizes search-demand data into several analytical levels:

- diagnostic area;
- keyword;
- region;
- time period.

The Tableau Public workbook contains three dashboards:

### Regional representation

Regional comparison of search demand by diagnostic area.

### Trends

Time-series analysis of demand dynamics.

### Keywords comparison

Comparison of individual search queries by current volume and growth.

Together, the dashboards support movement from a high-level regional view to more detailed analysis of diagnostic areas and individual keywords.

## Data

The public version uses a demonstration dataset prepared specifically for publication.

- Monthly nationwide Yandex Wordstat values are based on factual observations.
- Regional distribution is synthetic and was generated by interpolation.
- Regional values are validated so that their aggregate preserves the nationwide control total.
- The time scale is shifted by 100 years: **1920–1926 corresponds to 2020–2026**.
- Regional geometry is based on **geoBoundaries**.

The shifted timeline and synthetic regional allocation separate the demonstration dataset from the future automated loading of current data.

## Interpretation boundaries

Search demand is treated as a **proxy for user interest**, not as a direct measurement of:

- market size;
- sales;
- revenue;
- number of patients;
- actual utilization of diagnostic services.

Results therefore support comparative and exploratory analysis rather than direct market-volume estimation.

Diagnostic areas can contain multiple keywords, and the analytical model is designed around these relationships. Aggregated values should be interpreted within the defined analytical level rather than assumed to be additive across arbitrary groupings.


## Technical architecture

The working analytical environment uses:

- PostgreSQL 17;
- PostGIS;
- SQL-based analytical transformations;
- Tableau.

For publication, the database-dependent version was converted into a standalone Tableau Public workbook using prepared snapshot extracts and geographic data.

The analytical layer separates source/reference data, transformed analytical datasets, and presentation-oriented marts.
